## Reviewer notes

All three `sorry` warnings occur in the statement-side `Challenge.lean` of each
project (`affinecore:270`, `boussinesq-blowup:67`, `euler-blowup:56`). These files
state the comparator problem without proving it; the audited theorems come from
each project's `Solution.lean` and library modules.

Decisive check: `sorryAx` appears in no axiom output in this bundle. Each of the
six audited theorems depends on exactly `[propext, Classical.choice, Quot.sound]`.

No `error:` lines appear in any log.

Two properties of this bundle must be read alongside it:

1. Build mode is `resume` (see `build-mode.txt`). The harness reused existing work
   trees rather than re-cloning, after asserting that the tree sat at the exact
   pinned commit `d0124689230b58b4f86e7b90ac59de06404b3b6b` with a completely clean
   working tree (no modified tracked files, no untracked sources). Ignored build
   outputs under `.lake` were reused. The euler-blowup and boussinesq-blowup builds
   in this bundle are therefore largely cache replays; their from-scratch compiles
   occurred in earlier runs on the same pinned commit.

2. The build step names every `lean_lib` declared in each project's lakefile rather
   than relying on `defaultTargets`. This matters for affinecore, whose lakefile
   sets `defaultTargets = ["AffineCore"]` and omits the comparator pair. A bare
   `lake build` on affinecore exits 0 without ever compiling `Solution.lean` -- the
   file binding `forced_boussinesq_affine_core_blowup` to its proof -- and the
   project's own `scripts/PrintAxioms.lean` then fails with "unknown module prefix
   'Solution'". Anyone reproducing this result with a bare `lake build` will get a
   green build that verifies less than it appears to. euler-blowup and
   boussinesq-blowup already list both comparator libraries in `defaultTargets`, so
   naming every declared library changes nothing for them.

A clean build establishes that Lean accepted the pinned source with the pinned
toolchain and that the committed `PrintAxioms.lean` checks pass. It does not
establish that the formal statements faithfully encode the informal claims, and it
is not a substitute for mathematical review.
